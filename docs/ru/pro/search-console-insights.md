# Аналитика Search Console {#search-console-insights}

Пять отчётов на основе ваших собственных данных Search Console: запросы в выбранном диапазоне позиций, кандидаты на проверку CTR, пересечения запросов и страниц, группы запросов и изменения между периодами. Три используют синхронизированную историю, ещё два — один общий кешируемый сетевой запрос. Они выполняют эти конкретные виды анализа, а не заменяют полный набор данных и возможностей сторонней платформы ключевых слов.

В основе — [интеграция Search Console только для чтения](/ru/pro/search-console) и синхронизация её истории. Если описанная там команда `seo-pro:gsc-sync` уже выполняется, три из пяти отчётов работают **без дополнительных затрат на API**.

::: tip Предварительное условие
Три отчёта по *снимкам* читают сохранённую историю `seo_gsc_metrics`, поэтому сначала настройте расписание `seo-pro:gsc-sync`: см. [Search Console → история](/ru/pro/search-console). Чем больше дней синхронизировано, тем глубже сравнение динамики.
:::

## Пять отчётов {#the-five-surfaces}

### 1. Ключевые слова в диапазоне ближайших позиций {#_1-striking-distance-keywords}

Запросы, у которых **средняя позиция, взвешенная по показам, находится в диапазоне 5–20**, отсортированные по показам. Используйте их для проверки релевантности и внутренних ссылок. Сам диапазон не доказывает, что небольшое изменение выведет запрос на первую страницу.

### 2. Возможности улучшения CTR {#_2-ctr-opportunities}

Запросы, которые **занимают хорошие позиции, но получают клики реже ожидаемого** для этих позиций. Фактический CTR каждого запроса сравнивается с обобщённой отраслевой кривой CTR по позициям. Запросы с реальными показами и CTR заметно ниже ожидаемого становятся **кандидатами на переработку заголовка и описания**. Они сортируются по оценке *упущенных кликов*. Этот список удобно передать [генератору метаданных с ИИ](/ru/pro/ai-assist): он показывает конкретные запросы, ради которых стоит пересмотреть текст.

### 3. Каннибализация {#_3-cannibalization}

Запросы, по которым **появляются два или более ваших URL**. Пересечение не обязательно вредит: прежде чем объединять или разграничивать страницы, проверьте, отвечают ли они на разные намерения пользователей.

### 4. Группы запросов {#_4-query-clusters}

**Запросы, по которым каждая страница действительно ранжируется**, сгруппированные по странице: её реальный тематический охват с точки зрения Google. Это помогает заметить страницу, которая отклоняется от задуманной темы или незаметно получает позиции по ценному запросу, на который вы не ориентировались.

### 5. Динамика относительно прошлого периода {#_5-trend-vs-previous-period}

**Самые заметные изменения** кликов, показов, позиции и CTR между текущим окном и непосредственно предшествующим периодом той же длины. Позиция сравнивается только для запросов с трафиком в обоих периодах: у совершенно нового или полностью исчезнувшего запроса нет сопоставимой позиции.

## Откуда берутся числа: сетевые данные и снимки {#where-the-numbers-come-from-live-vs-snapshot}

Каждый отчёт читает источник, который даёт правильный ответ с наименьшими затратами. Сохранённая история не позволяет восстановить, какой **запрос** связан с какой **страницей**: эти измерения хранятся отдельно. Поэтому только два отчёта, которым нужна такая пара, обращаются к сети — и **используют один общий кешируемый запрос**.

| Отчёт | Источник | Причина |
|---|---|---|
| Ближайшие позиции | **Локальный снимок** | Нужны позиция и показы по запросу; они уже есть в синхронизированной истории, без затрат на API. |
| Возможности CTR | **Локальный снимок** | Те же собственные данные; кривая ожидаемого CTR — статический ориентир, а не сетевой поиск. |
| Изменения динамики | **Локальный снимок** | Нужна настоящая история по дням, которую и сохраняет синхронизация. |
| Каннибализация | **Сеть** — запрос × страница | Связь запроса со страницей не хранится; сохранение всех пар многократно увеличило бы объём данных. |
| Группы запросов | **Сеть** — *общая загрузка с отчётом 3* | Те же пары, сгруппированные по страницам вместо запросов. |

Поэтому посещение страницы аналитики требует **не более одного** запроса Search Analytics, который кешируется на `search_console.cache_ttl` секунд. Отчёты по парам намеренно используют сетевые данные: для каннибализации и группировки нужна картина *на определённый момент*, а общий кеш ограничивает повторы. Обновление токена может потребовать дополнительного запроса аутентификации, и квоты Google по-прежнему действуют. Отчёты по снимкам никогда не обращаются к сети.

## В панели управления {#in-the-dashboard}

С установленным плагином Filament в группе *SEO* появляется страница **Search Console Insights** — название в английском интерфейсе. Она видна только при включённой интеграции и строго доступна только для чтения. Каждый отчёт показан отдельным разделом; пустые разделы со снимками предлагают синхронизировать историю, а неудачная сетевая загрузка пар выводит очищенное от чувствительных данных уведомление внутри раздела, не блокируя страницу.

## Конфигурация {#configuration}

Все параметры находятся в `search_console.insights` файла `config/seo-pro.php`. Значения по умолчанию подходят для начала; подстройте пороги под масштаб сайта.

```php
'search_console' => [
    // ...
    'insights' => [
        // Rolling window (days) the snapshot surfaces aggregate over,
        // anchored to the latest synced day.
        'window_days' => 28,

        // Max rows a surface returns to its panel section.
        'max_rows' => 50,

        // (1) Striking distance: impression-weighted position in [min,max]
        // with at least this many impressions.
        'striking_distance' => [
            'min_position' => 5.0,
            'max_position' => 20.0,
            'min_impressions' => 30,
        ],

        // (2) CTR opportunity: queries ranking at/above max_position, with at
        // least min_impressions, whose CTR is at least min_gap_ratio below the
        // expected curve.
        'ctr_opportunity' => [
            'max_position' => 10.0,
            'min_impressions' => 50,
            'min_gap_ratio' => 0.30,
        ],

        // Optional override of the expected CTR-by-position curve
        // (position => percent). null uses the built-in blended curve.
        'ctr_curve' => null,

        // (3) Cannibalization: a query with this many URLs each drawing at
        // least min_impressions.
        'cannibalization' => [
            'min_urls' => 2,
            'min_impressions' => 10,
        ],

        // (4) Query clustering: queries per page above min_impressions.
        'clustering' => [
            'min_impressions' => 10,
            'max_queries_per_page' => 15,
        ],

        // (5) Trend deltas: surface queries with at least this many
        // impressions in either period.
        'trend' => [
            'min_impressions' => 20,
        ],

        // The shared live (query,page) fetch for surfaces 3 + 4.
        'pair_days' => 28,
        'pair_row_limit' => 5000,
    ],
],
```

::: info Кривая ожидаемого CTR
Кривая возможностей CTR — **эвристика**, объединяющая опубликованные средние значения органического CTR по позициям. Это ориентир, а не утверждение о вашем конкретном сайте. Отмеченный запрос — *кандидат на проверку*, а не доказанная проблема. Если у вас есть собственная измеренная кривая, укажите её в `insights.ctr_curve` как карту `position => percent`.
:::
